# README.cm-ord-visibility.md

Правила видимости Ord-блоков «продолжения» в комах — блоков с флагами `isAnchorInherit` / `isAnchorInheritPlus`, то есть реплик продолжений ссылочного блока, размещенных под якорем.
Читай этот файл перед изменением геттера `isVisible` у `CmComOrder` (`src/shared/const/cm/order/Order.ts`) или переключателей наследования якоря.

## Правила

> **РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ ОКОНЧАТЕЛЬНЫ:** никогда не откатывай и не пересматривай их.

1. Видимость блока — первое не-nil значение плоской цепочки по приоритету: `com.intp` (`com.intp.o[wid].v`); `self.v` — собственное `v` исходника блока (`me.source.top.v`, без слитых значений; для `isAnchorInherit` звено пропущено — его данные совпадают со `watchOrd.top.v` и не должны перекрывать `leadOrd._v`); `leadOrd._v` (`leadOrd.me.source.top._v[inhi]`, только для `isAnchorInherit`); `watchOrd.v` (`watchOrd.me.source.top._v[inhi] ?? watchOrd.top.v`, только для `isAnchorInherit`); `targetOrd.v` (`top.v` блока, на который ссылается якорь). Здесь `inhi` = `anchorInheritIndex`.
2. Правило по умолчанию, когда вся цепочка дала nil: блок с `leadOrd` (`isInherit`, `isAnchorInherit`, `isAnchorInheritPlus`) следует за состоянием `leadOrd` — скрытый лид скрывает продолжение; блок без `leadOrd` видим.
3. Правило переопределения: явное `1`/`0` из цепочки важнее состояния лида — `1` показывает блок даже под скрытым лидом, `0` скрывает даже под видимым.
4. Никакого мусора в данных: бэкендовый переключатель `toggleAnchorInhVis` (`src/back/apps/cm/edit-com-order.tsjrpc.base/index.ts`) должен оставаться полезным в любом состоянии лида — он очищает `_v[inhi]`, перечитывает видимость и записывает значение только если оно доказуемо меняет следующее чтение (`isVisible ? 0 : 1`, когда сброс не переключил видимость).
5. Существующие сохраненные записи `_v` не требуют миграции или очистки.
6. Блоки `isAnchorInheritPlus` не имеют переопределений по индексу (оба геттера наследования возвращают nil для них) — они управляются исключительно лидом.

Для `isAnchorInherit` `wid` синтетический, поэтому записи `com.intp` для них обычно отсутствуют; слитый `top` реплик в цепочку не входит — `v` ссылочного блока доходит только через звено `targetOrd.v`, ниже явного переопределения `leadOrd._v`, поэтому переключатель Eye всегда может показать или скрыть продолжение.

## Словарь

- `leadOrd` — «первый орд цепочки наследования»: для `isAnchorInherit` — сам якорь (его `_v[inhi]` задает переопределения реплик); для `isInherit` / `isAnchorInheritPlus` — предшествующий блок (обычно якорь), за состоянием которого следует продолжение.
- `watchOrd` — «тот же орд у рефа»: для `isAnchorInherit` — оригинальный экземпляр продолжения в исходном месте (его `_v[inhi]` / `top.v` дают значение по умолчанию); у якоря `watchOrd` совпадает с `targetOrd`.
- `targetOrd` — блок, на который указывает якорь (`top.a`); его `top.v` — замыкающий источник цепочки.

## Краткая справка

| Флаг блока            | Цепочка после `com.intp` / `self.v`               | Видимость определяется                                |
| --------------------- | ------------------------------------------------- | ----------------------------------------------------- |
| обычный блок          | —                                                 | первым не-nil; иначе видим                            |
| `isInherit`           | —                                                 | первым не-nil; иначе состоянием `leadOrd`             |
| `isAnchorInherit`     | `leadOrd._v[inhi]` → `watchOrd.v` → `targetOrd.v` | первым не-nil; иначе состоянием лида                  |
| `isAnchorInheritPlus` | — (геттеры дают nil, `targetOrd` отсутствует)     | первым не-nil; иначе состоянием лида                  |

`targetOrd` есть только у якорных блоков — у остальных типов цепочка после `self.v` пуста и решает правило по умолчанию.

## Умный поиск

- Фильтр `BackLocaleKey.CmSmartSearchAnchorsAndAnchorPlus` («Песни с якорями и якорь+») отбирает комы, в разобранном списке ордов которых (`new CmCom(...).setOrders()`) есть орды с `isAnchorInherit` и орды с `isAnchorInheritPlus`; при ошибке разбора ком пропускается.
- Реализован в `src/back/apps/cm/editor.tsjrpc.base.ts`: пункт списка в `getSmartSearchFilters` и ветка `case` в `getSmartSearchComws`.
- Оба флага выставляет `cmComOrderListConstructor` (`src/shared/utils/cm/com/orderListConstructor.ts`), причем `isAnchorInheritPlus` ставится только при наличии у цели якоря inherit-продолжений — поэтому любой подходящий ком содержит оба вида.

## Проверка

- [ ] Явное `1`/`0` из цепочки побеждает состояние лида в обе стороны.
- [ ] Продолжение под скрытым лидом скрыто, пока вся цепочка дала nil и лид скрыт.
- [ ] Продолжение под видимым лидом скрывается только явным `0`.
- [ ] `toggleAnchorInhVis` никогда не сохраняет значение, оставляющее следующее чтение неизменным.
- [ ] Eye (`toggleAnchorInhVis`) показывает продолжение, даже если ссылочный блок хранит `v: 0`, и скрывает его повторным нажатием.
- [ ] Скрытый якорь скрывает все свои реплики, кроме явно показанных (`_v[inhi]` = 1); явно скрытые (`0`) и без значения — скрыты.
