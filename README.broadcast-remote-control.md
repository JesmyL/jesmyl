# README.broadcast-remote-control.md

Система «пульт экрана» для broadcast: пользователь подключается к экрану трансляции со своего устройства и управляет показом, а экран решает, кому разрешить подключение.
Читай этот файл перед любой работой над пультом broadcast — правила ниже авторитетны.

## Точки входа на пульт конкретного экрана

Входов ровно две: по QR-коду и из списка.
Выбор между ними определяется query-параметрами: `from-list` + `fio`.

- Есть ОБА параметра — вход из списка.
- Отсутствует хотя бы один — вход по QR-коду (прямая ссылка — это то же самое, что QR-код).

## Вход по QR-коду

- Экран запрашивает имя подключающегося: сервер экрана отвечает ошибкой `NameRequired`, пульт показывает usePrompt **«Представьтесь»**.
- Имя запоминается на пульте.
- При следующем входе по QR имя переспрашивается, причём предыдущее значение из памяти пульта передаётся в usePrompt как default-value.
- На экран каждый раз передаётся актуальное имя с пульта — в том числе новое, если пользователь перезаписал его в prompt.
- На стороне экрана показывается useConfirm о разрешении подключиться: подтверждение — устройство одобрено, отказ — ban.
- Подтверждение (и переспрос имени) требуется при каждом QR-входе — даже если устройство уже было одобрено ранее, — но только ОДИН раз за сессию страницы пульта: от подключения до закрытия страницы.
- Переподключения внутри одной сессии страницы (обрыв связи и восстановление) имя и подтверждение повторно не запрашивают.
- Новое открытие страницы пульта — новая сессия: имя и подтверждение запрашиваются снова.

## Вход из списка (query: `from-list` + `fio`)

- Разрешение на вход не запрашивается.
- usePrompt **«Представьтесь»** не показывается — имя берётся из query-параметра `fio`.
- Значение `fio` показывается в списке подключений на экране.
- Если пользователь ранее заходил по QR-коду, рядом с его `fio` в скобках указывается имя, которым он представился через prompt: `fio (имя из prompt)`.
- Скобки не дублируются, если значения совпадают.

## Production specifics (продакшен-особенности)

- Страница пульта живёт на origin экрана (`http://<LAN-IP>:<порт>`), где авторизация jesmyl в IndexedDB пуста и вход невозможен — `user`/`jesmylToken` доходят до сервера только из сессии пульта, открытой на origin `jesmyl.ru`. На origin экрана показываемое имя — это query-параметр `fio` (для входов из списка он И ЕСТЬ имя авторизации) либо имя из prompt (для входов по QR).
- Приоритет отображения имени подключения: сначала auth-идентичность (`fio | nick | email | login`, через `takeUserAuthName`), затем имя из prompt / параметра `fio`, затем `deviceId`; имя, данное в prompt, дописывается в скобках (`promptName`), когда оно отличается.
- Цветовая гамма экрана доходит до пультов ТОЛЬКО через WS-сообщение `Scheme` (экран → пульт): фронт-релей экрана читает `indexIDB.appColorGamutIndex` и вызывает `sendScreenScheme`; пульт применяет класс `gamut-N` (`PultThemeSync`). Если гамма не подхватывается — проверяй свежесть фронтов (см. следующий пункт).
- Фронт пульта НЕ скачивается electron'ом с сайта напрямую (ни `pult-assets.json`, ни файлы по одному). Файлы пульта (`pult.html`, его чанки, `pult-assets.json`) входят в SW-прекэш сайта (`vite-pwa.options.ts`), и при КАЖДОМ старте приложения фронт сайта внутри electron-окна дожидается свежего service worker (`update()` + `SKIP_WAITING` + `controllerchange`), читает файлы пульта из своего SW-кэша и передаёт их в electron методом `sharePultFrontFiles` (`pult-front-sync.ts` → `front-cache.ts`): electron атомарно подменяет кэш `userData/remote-front/active` и рассылает пультам `Version`. Если пульт на проде отдаёт старый код — перезапусти приложение экрана после редеплоя сайта: свежая версия приходит при старте.
- Версия фронта пульта — это `num` из `src/shared/values/+version.json`, она же в `pult-assets.json`. Если задеплоить изменение с пропуском инкремента версии, электрон молча отбросит новый пульт (проверка монотонности версии) — не деплой пульт без бампа версии.
